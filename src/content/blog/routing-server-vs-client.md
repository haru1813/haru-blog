라우팅(Routing)은 한마디로 **"주소(URL)를 보고, 어디로 보낼지 정하는 것"**이다. 개념 자체는 단순한데, 웹에서는 이게 **두 곳에서 서로 다르게** 일어난다. 하나는 서버에서, 하나는 브라우저에서. 이 둘을 헷갈리면 "왜 새로고침이 되지?", "왜 이 URL은 404가 나지?" 같은 데서 막힌다. 정리해 둔다.

## 서버 사이드 라우팅 — 서버가 페이지를 만들어 준다

전통적인 방식이다. 브라우저가 URL을 요청하면, **서버가 그 URL에 맞는 처리를 찾아(라우팅) 완성된 HTML을 만들어 응답**한다.

```java
// Spring
@GetMapping("/users/{id}")
public String userPage(@PathVariable Long id, Model model) {
    // DB 조회 후 HTML 페이지를 만들어 응답
    return "user";
}
```

- 페이지를 이동할 때마다 **서버에 새 요청**을 보낸다.
- 그때마다 **전체 페이지가 새로고침**된다.
- 이렇게 여러 페이지가 서버에서 각각 만들어지는 앱을 **MPA(Multi Page Application)**라 한다. (PHP·JSP·전통적 Spring MVC가 이 방식)

장점은 **SEO에 유리**하고(검색엔진이 완성된 HTML을 바로 읽음), 초기 화면이 빠르다는 것. 단점은 이동마다 서버를 왕복하며 화면이 깜빡인다는 것이다.

## 클라이언트 사이드 라우팅 — 브라우저가 화면을 바꾼다

React·Vue 같은 SPA(Single Page Application)에서 쓰는 방식이다. 여기선 **처음 한 번만** HTML·JS를 받아 오고, 그다음부터는 **서버에 페이지를 다시 요청하지 않는다.** URL이 바뀌어도 **JavaScript(라우터)가 화면(컴포넌트)만 갈아 끼운다.**

```jsx
// React Router
<Routes>
  <Route path="/users/:id" element={<UserPage />} />
</Routes>
```

- URL이 `/users/1` → `/users/2`로 바뀌어도 **서버 요청도, 새로고침도 없다.**
- 라우터가 URL을 보고 **해당 컴포넌트로 화면만 교체**한다.
- 그래서 페이지 전환이 **앱처럼 매끄럽다.**

## 결정적 차이 — 새로고침이 있느냐

| | 서버 사이드 | 클라이언트 사이드 |
|---|---|---|
| 누가 라우팅 | 서버 | 브라우저(JS) |
| 이동 시 | 서버에 요청 + 새로고침 | 요청 없이 화면만 교체 |
| 대표 | Spring MVC, PHP | React Router, Vue Router |
| 앱 형태 | MPA | SPA |
| SEO | 유리 | 신경 써야 함 |

## 클라이언트 라우팅은 어떻게 새로고침 없이 URL을 바꿀까

비밀은 브라우저의 **History API**다. `history.pushState()`로 **주소창의 URL은 바꾸되, 서버에는 요청을 보내지 않는다.** 라우터는 이 바뀐 URL을 감지해서 알맞은 컴포넌트를 그린다. 즉 "주소는 바뀌었는데 페이지는 안 넘어간 것처럼" 보이는 마법이 여기서 나온다.

## SPA에서 자주 만나는 함정 — 새로고침하면 404

클라이언트 라우팅에는 유명한 함정이 있다. `/users/1` 화면에서 **새로고침(F5)**을 누르면 404가 뜨는 경우다.

- 이유: 새로고침은 그 URL을 **서버에** 요청한다. 그런데 서버에는 `/users/1`이라는 경로가 **없다**(라우팅은 브라우저 JS가 하니까). 그래서 서버가 "그런 페이지 없음(404)"이라 답한다.
- 해결: 서버가 **모든 경로를 `index.html`로 돌려주도록** 설정한다. 그러면 일단 SPA가 로드되고, 그다음 브라우저 라우터가 `/users/1`을 처리한다.

이 하나만 알아도 SPA 배포할 때 헤맬 일이 줄어든다.

## 정리

- **라우팅**: 주소(URL)를 보고 어디로 보낼지 정하는 것.
- **서버 사이드**: 서버가 URL마다 페이지를 만들어 응답. 이동 시 새로고침. (MPA · Spring MVC)
- **클라이언트 사이드**: 브라우저가 화면만 교체, 새로고침 없음. (SPA · React Router)
- **핵심 갈림길**: 이동할 때 **서버를 왕복하느냐, 브라우저가 알아서 하느냐.**

같은 "라우팅"이라는 단어지만, **어느 쪽에서 길을 정하느냐**가 완전히 다른 경험을 만든다. 서버에서 만들던 페이지를 브라우저가 직접 그리게 된 것 — 그게 MPA에서 SPA로 넘어온 흐름의 핵심이었다.
