[배경 글](/blog/frontend-spa-ssr/)에서 React·Vue가 둘 다 *"SPA를 편하게 만들려고"* 나왔다고 했다. 목적이 같은데 왜 둘일까? **접근 방식이 다르기** 때문이다. 무엇이 다르고, 언제 뭘 쓰는지 정리한다.

## 공통점부터 — 뿌리는 같다

먼저 둘의 **공통 뼈대**를 잡자. 사실 많이 닮았다.

- **컴포넌트 기반** — UI를 재사용 가능한 조각으로
- **상태(state) → 화면 자동 갱신** — 데이터가 바뀌면 화면이 따라감
- **가상 DOM** — 바뀐 부분만 효율적으로 다시 그림
- **SPA** 제작 도구

그래서 하나를 알면 다른 하나도 빨리 익힌다. 차이는 **"같은 걸 어떻게 표현하고 관리하느냐"** 에 있다.

## 차이 ① 라이브러리 vs 프레임워크

```
React → 라이브러리 (UI만 담당, 나머진 골라 끼움)
Vue   → 프레임워크 (라우팅·상태관리 등 공식 세트 제공)
```

- **React** — **UI 렌더링만** 책임진다. 라우팅(React Router)·상태관리(Redux/Zustand)는 **직접 골라** 조합한다. 자유롭지만 **선택지가 많아** 처음엔 막막할 수 있다
- **Vue** — **공식 세트**(라우터·Pinia 등)가 있어 정해진 길을 따라가면 된다. 덜 헷갈리지만 그만큼 정해진 방식

React는 *"레고 블록을 네가 골라 조립해"*, Vue는 *"조립 설명서를 줄게"* 에 가깝다.

## 차이 ② JSX vs 템플릿

화면을 그리는 **문법**이 다르다.

**React — JSX (자바스크립트 안에 HTML)**
```jsx
function Hello({ name }) {
  return <h1>안녕, {name}!</h1>;   // JS 함수가 HTML을 반환
}
```
JS 코드 안에서 HTML을 쓴다. *"자바스크립트가 중심, HTML이 그 안에"* 다.

**Vue — 템플릿 (HTML 확장)**
```vue
<template>
  <h1>안녕, {{ name }}!</h1>   <!-- HTML에 문법을 얹음 -->
</template>
<script setup>
defineProps(['name'])
</script>
```
HTML을 그대로 쓰되 `{{ }}`·`v-if`·`v-for` 같은 **디렉티브**를 얹는다. *"HTML이 중심, 거기에 기능을 추가"* 다.

HTML/CSS에 익숙하면 Vue 템플릿이 친숙하고, JS에 익숙하면 React JSX가 자연스럽다.

## 차이 ③ 명시적 vs 반응형(자동)

상태가 바뀔 때 화면을 갱신하는 **방식**이 다르다. 이게 가장 근본적인 차이다.

**React — 명시적 (내가 갱신을 알림)**
```jsx
const [count, setCount] = useState(0);
setCount(count + 1);   // "상태 바뀌었다"고 setState로 명시적으로 알림
```
상태를 바꿀 땐 **반드시 `setState`(setCount)로 알려야** React가 다시 그린다. 명시적이라 흐름이 예측 가능하다.

**Vue — 반응형 (알아서 추적)**
```js
const count = ref(0);
count.value++;   // 그냥 바꾸면 Vue가 "어, 바뀌었네" 하고 자동 갱신
```
값을 **그냥 바꾸면** Vue가 변화를 **자동으로 추적**해 화면을 갱신한다. 편하지만 "뒤에서 마법처럼" 도는 느낌이 있다.

```
React → "바뀌었어!" 하고 손들어야 갱신 (명시적, 예측 쉬움)
Vue   → 바꾸기만 하면 알아서 갱신 (반응형, 편함)
```

## 비교표

| | React | Vue |
|---|---|---|
| 성격 | 라이브러리 (UI만) | 프레임워크 (세트 제공) |
| 문법 | **JSX** (JS 중심) | **템플릿** (HTML 중심) |
| 상태 갱신 | **명시적** (`setState`) | **반응형** (자동 추적) |
| 만든 곳 | Meta(페이스북) | Evan You(개인→커뮤니티) |
| 생태계 | **매우 큼** | 크지만 React보단 작음 |
| 러닝 커브 | 다소 높음 | **낮음** (진입 쉬움) |

## 그래서 언제·왜 쓰나

```
React가 유리할 때:
  · 대규모 앱, 큰 생태계·라이브러리 필요
  · React Native로 모바일도 (같은 문법)
  · 채용 시장이 큼 (일자리 많음)
  · 자유로운 구조를 원할 때

Vue가 유리할 때:
  · 빠른 시작·낮은 러닝 커브 (HTML/CSS 친숙하면 특히)
  · 정해진 길을 따라 빠르게 개발
  · 문서가 친절 (한국어 포함 잘 됨)
  · 중소 규모·개인 프로젝트
```

**둘 다 훌륭하고, 우열이 아니라 취향·상황의 문제**다. 다만 **취업·생태계 관점에선 React가 우세**해서, 하루님처럼 [HaruVerse](/) 같은 걸 만들며 커리어로 이어갈 거면 **React를 주력**으로 하고 Vue를 비교로 이해하는 게 실용적이다.

## 정리

- **공통** — 컴포넌트·상태 기반 SPA, 가상 DOM (뿌리는 닮음)
- **차이 셋**:
  - **라이브러리(React)** vs **프레임워크(Vue)** — 골라 끼움 vs 세트 제공
  - **JSX(React)** vs **템플릿(Vue)** — JS 중심 vs HTML 중심
  - **명시적(React)** vs **반응형(Vue)** — setState vs 자동 추적
- **선택** — 대규모·생태계·모바일·채용이면 React / 빠른 시작·낮은 러닝커브면 Vue

React와 Vue는 *"어느 게 정답"* 이 아니라, **같은 문제(SPA)를 다른 철학으로 푼 것**이다 — React는 "명시적이고 자유롭게", Vue는 "편하고 정해진 길로". 이 차이를 알면 둘 중 하나를 배울 때도 *"아, 저쪽은 이렇게 하겠구나"* 하고 서로가 비춰준다. 다음은 [실제로 개발환경을 세팅](/blog/frontend-dev-setup/)해 손으로 시작해본다. 결국 여기서도 방향은 하나였다 — 같은 목적지를, 다른 길로 오른다.
