컴포넌트를 만들었으면, 이제 **가진 데이터를 화면에 보여줄** 차례다. 변수에 담긴 값을 UI에 연결하는 것 — 이걸 **데이터 바인딩(data binding)**이라 한다. React는 `{}`, Vue는 `{{}}`로 한다. 둘을 나란히 놓고 정리한다.

## React — JSX 표현식 `{}`

React는 출력이 **중괄호 하나 `{}`** 로 고정이다. 다만 [작성 방식](/blog/react-vs-vue/)에 따라 **변수를 선언하는 위치**가 다르다.

**함수형 컴포넌트 (현대 표준)**
```jsx
function App() {
  const name = "하루";        // 함수 안에 변수
  const age = 34;
  return (
    <div>
      <h1>{name}</h1>         {/* {} 안에 변수 → "하루" */}
      <p>나이: {age}</p>       {/* "나이: 34" */}
    </div>
  );
}
```

**클래스 컴포넌트 (레거시)**
```jsx
class App extends React.Component {
  render() {
    const name = "하루";      // render() 안에 변수
    const age = 34;
    return (
      <div>
        <h1>{name}</h1>       {/* 출력은 똑같이 {} */}
        <p>나이: {age}</p>
      </div>
    );
  }
}
```

**변수 선언 위치만 다르고**(함수 안 vs `render()` 안), **출력은 둘 다 `{}`** 로 똑같다. `{}`는 *"여기에 자바스크립트 값을 넣어라"* 는, JSX 안에서 JS로 들어가는 창이다.

## Vue — 텍스트 보간 `{{}}`

Vue는 출력이 **중괄호 둘 `{{}}`** 로 고정이다 (이 `{{}}`를 **보간**, mustache라 부른다). 역시 [작성 방식](/blog/react-vs-vue/)에 따라 선언이 다르다.

**Composition API (권장)**
```vue
<script setup>
const name = "하루"          // const로 선언
const age = 34
</script>

<template>
  <div>
    <h1>{{ name }}</h1>      <!-- {{}} 안에 변수 → "하루" -->
    <p>나이: {{ age }}</p>    <!-- "나이: 34" -->
  </div>
</template>
```

**Options API**
```vue
<script>
export default {
  data() {
    return { name: "하루", age: 34 }   // data() 옵션에 담아 반환
  }
}
</script>

<template>
  <div>
    <h1>{{ name }}</h1>      <!-- 출력은 똑같이 {{}} -->
    <p>나이: {{ age }}</p>
  </div>
</template>
```

선언이 **`const`(Composition) vs `data()` 반환(Options)** 으로 다르고, **출력은 둘 다 `{{}}`** 로 똑같다.

## 나란히 비교

| 스타일 | 변수 선언 위치 | 출력 |
|---|---|---|
| React **함수형** | 함수 안 `const` | `{name}` |
| React **클래스** | `render()` 안 `const` | `{name}` |
| Vue **Composition** | `<script setup>`의 `const` | `{{ name }}` |
| Vue **Options** | `data()` 반환 | `{{ name }}` |

```
React (함수형·클래스) → { }   (중괄호 하나)
Vue   (Composition·Options) → {{ }} (중괄호 둘)
```

핵심은 두 가지다:
- **출력 문법은 프레임워크별로 고정** — React는 `{}`, Vue는 `{{}}` (스타일이 뭐든 안 바뀜)
- **변수 선언 위치만 스타일별로** 다름 — 함수 안 / `render()` 안 / `script setup` / `data()`

그래서 어느 쪽 코드인지는 **중괄호 개수**로, 어떤 스타일인지는 **선언 위치**로 알아본다.

## 중괄호 안엔 "표현식"이 들어간다

단순 변수만이 아니라, **자바스크립트 표현식**을 넣을 수 있다. 계산·문자열 조합·삼항연산자 등.

```jsx
{/* React */}
<p>{age + 1}</p>              {/* 35 */}
<p>{name + "님"}</p>          {/* 하루님 */}
<p>{age >= 20 ? "성인" : "미성년"}</p>   {/* 성인 */}
```

```vue
<!-- Vue -->
<p>{{ age + 1 }}</p>          <!-- 35 -->
<p>{{ name + "님" }}</p>       <!-- 하루님 -->
<p>{{ age >= 20 ? "성인" : "미성년" }}</p>
```

문법(`{}` vs `{{}}`)만 다르지, **안에 넣는 표현식은 똑같은 자바스크립트**다. 그래서 한쪽을 알면 다른 쪽도 금방 익는다.

## 여기서 경계 하나 — "안 바뀌는 값"이다

지금까지 출력한 `name`·`age`는 **정적인 값**이다. 한 번 그려지면 그대로다. 그런데 실제 앱에선 값이 **바뀌면 화면도 따라 바뀌어야** 한다 (버튼 누르면 숫자 증가 등).

```jsx
// ❌ 이렇게 그냥 변수를 바꾸면 — 화면이 안 바뀐다!
let count = 0;
count = count + 1;   // 값은 바뀌지만 React는 다시 안 그림
```

**바뀌면 화면이 갱신되는 값**은 그냥 변수가 아니라 **상태(state)** 로 다뤄야 한다 — React는 `useState`, Vue는 `ref`다. 이게 [React vs Vue 글](/blog/react-vs-vue/)에서 본 *"명시적(setState) vs 반응형(자동)"* 의 그 지점이다. 이 **상태** 이야기는 다음 단계에서 이어진다.

## 정리

- **데이터 바인딩** = 변수 값을 화면에 연결하는 것
- **React** — 변수는 함수 안 `const`, 출력은 **`{변수}`**(JSX 표현식, 중괄호 1개)
- **Vue** — 변수는 `<script setup>`, 출력은 **`{{ 변수 }}`**(텍스트 보간, 중괄호 2개)
- **중괄호 안엔 JS 표현식** — 계산·조합·삼항 다 됨 (문법만 다르고 내용은 같은 JS)
- **경계** — 지금은 **안 바뀌는 값**. 바뀌면 화면이 갱신되는 값은 **상태(state)**(`useState`/`ref`)로 → 다음 단계

값을 화면에 꽂는 건 프론트의 가장 기본 동작이면서, `{}`와 `{{}}`라는 작은 차이로 React와 Vue의 결이 처음 갈리는 지점이기도 하다. 여기까지가 **정적인 화면**이고, 여기에 *"바뀌면 다시 그려지는"* 힘을 더하는 게 **상태**다 — 그때부터 화면이 살아 움직이기 시작한다.
