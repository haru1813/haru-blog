백엔드를 시작하면 "웹 서버(Web Server)"와 "웹 애플리케이션 서버(WAS)"라는 말을 자주 만난다. 둘 다 "서버"이고 둘 다 HTTP를 다루다 보니 처음엔 경계가 흐릿하다. 하지만 이 둘은 **하는 일이 분명히 다르고**, 실무에서는 대개 **함께** 쓴다. 정리해 둔다.

## 웹 서버 — 정해진 것을 빠르게 돌려준다

웹 서버는 **정적 리소스**를 처리한다. HTML·CSS·JavaScript·이미지처럼 **이미 만들어져 있는 파일**을 HTTP 요청에 맞춰 그대로 돌려주는 역할이다.

- 대표 주자: **Apache HTTP Server**, **Nginx**
- 요청이 오면 → 해당 파일을 찾아 → 응답한다. 계산도, DB 조회도 없다.
- 그래서 **빠르고 가볍다.** "바뀌지 않는 것"을 다루기 때문이다.

동적인 요청(예: `/orders/1204` 같은, 매번 결과가 달라지는 것)이 오면 웹 서버는 스스로 처리하지 못한다. 대신 **뒤에 있는 WAS로 넘긴다.**

## WAS — 매번 다른 답을 만들어낸다

WAS(Web Application Server)는 **동적 콘텐츠**를 담당한다. 요청을 받아 **비즈니스 로직을 실행**하고, 필요하면 **DB를 조회**해서, 그 결과로 응답을 **매번 새로 만들어낸다.**

- 대표 주자: **Tomcat**, WildFly(JBoss), WebLogic, WebSphere
- Java 진영에서는 Servlet·JSP를 실행하는 컨테이너가 그 핵심이다. (엄밀히 Tomcat은 "서블릿 컨테이너"라 불리는 경량 WAS다.)
- "회원가입", "주문 조회", "결제"처럼 **매번 결과가 달라지는 일**은 전부 WAS의 몫이다.

즉 웹 서버가 *"창고에서 물건을 꺼내 주는 사람"*이라면, WAS는 *"주문을 받아 즉석에서 요리하는 주방"*이다.

## 한눈에 보는 차이

| | 웹 서버 | WAS |
|---|---|---|
| 다루는 것 | 정적 리소스(HTML·이미지 등) | 동적 콘텐츠(로직·DB 결과) |
| 하는 일 | 있는 파일을 돌려줌 | 로직 실행 + 응답 생성 |
| 예시 | Apache, Nginx | Tomcat, WebLogic |
| 특징 | 빠르고 가벼움 | 유연하지만 상대적으로 무거움 |

## 그런데 왜 굳이 함께 쓸까

"WAS도 정적 파일을 줄 수 있는데(실제로 Tomcat도 가능하다), 왜 웹 서버를 앞에 또 두지?"

이유는 세 가지다.

**1. 역할 분리.** 정적 요청은 빠른 웹 서버가 처리하고, WAS는 **동적 로직에만 집중**하게 한다. WAS가 이미지·CSS까지 다 처리하면 정작 중요한 로직 처리에 쓸 자원이 줄어든다.

**2. 성능과 부하 분산.** 웹 서버(Nginx)를 앞에 두면 **리버스 프록시**로서 여러 WAS에 요청을 나눠 보낼 수 있다(로드 밸런싱). 트래픽이 늘어도 WAS를 여러 대로 늘려 대응한다.

**3. 보안.** WAS를 외부 인터넷에 직접 노출하지 않는다. **웹 서버가 앞단 방패** 역할을 하고, WAS는 내부망에 숨긴다.

그래서 전형적인 구조는 이렇다.

```
클라이언트
   │  HTTP
   ▼
[ Nginx (웹 서버) ]  ── 정적 요청이면 여기서 바로 응답
   │  동적 요청만 전달 (리버스 프록시)
   ▼
[ Tomcat (WAS) ]  ── 로직 실행
   │
   ▼
[ DB ]
```

## PHP에서 Spring으로 오며 느낀 것

내가 이 구조를 몸으로 느낀 건 스택을 옮기면서였다.

- **PHP** 시절에는 보통 **Apache + mod_php** 조합을 썼다. 웹 서버(Apache)가 PHP 실행까지 모듈로 끌어안는 형태라, 웹 서버와 애플리케이션의 경계가 눈에 잘 안 들어왔다. (요즘은 **Nginx + PHP-FPM**으로 이 둘을 분리하는 추세다.)
- **Spring Boot**로 오니 **내장 톰캣(embedded Tomcat)**이 딸려 왔다. 별도 WAS를 설치하지 않아도 `java -jar`로 애플리케이션이 곧 WAS로 뜬다. 개발은 간편해졌지만, 운영에서는 그 앞에 **Nginx를 리버스 프록시로 두는** 경우가 많다 — 위에서 말한 그 이유들 때문이다.

결국 도구와 언어는 달라도 **"정적은 웹 서버가, 동적은 WAS가, 그리고 웹 서버가 앞단을 지킨다"**는 뼈대는 똑같았다.

## 정리

- **웹 서버**: 정해진 정적 리소스를 빠르게 돌려준다. (Apache, Nginx)
- **WAS**: 로직을 실행하고 DB를 거쳐 응답을 매번 만들어낸다. (Tomcat 등)
- **함께 쓰는 이유**: 역할 분리 · 성능/부하 분산 · 보안.

처음엔 헷갈리지만, *"창고 담당 / 주방 담당"*으로 나눠 보면 한 번에 정리된다. 다음엔 이 앞단에 리버스 프록시와 로드 밸런서를 어떻게 얹는지 정리해 볼 생각이다.
